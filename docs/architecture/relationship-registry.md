# 关系类型注册表与当前图投影

## 模型

关系不是任意字符串。`RelationshipType` 声明正向/反向名称、有向性、允许的源和目标实体
类型、两端基数、限定字段 Schema、证据要求及不可变版本。`EntityType` 再声明它允许产生
哪些关系，形成双重约束。

关系实例保存在实体不可变修订中，包含源/目标 `EntityRef`、限定字段、置信度、引用和修订
ID。PostgreSQL `relation_edge` 只保存当前修订的可查询投影；历史事实仍由实体修订 JSON
保留，因此回放和回滚不依赖独立图数据库。

## 写入校验

`KnowledgeRepository.save_entity` 在同一事务中检查：

- 源引用必须属于当前实体，目标实体必须存在且类型一致；
- 源实体类型允许该关系，关系类型允许源/目标类型；
- 引用必须存在于当前实体修订，必需证据不能为空；
- 限定字段名称、基本类型与枚举必须符合声明；
- `one` 基数在当前投影和同批新关系中均不得重复；
- 关系 ID、实体修订 ID 和当前投影保持一致。

任一检查失败会回滚实体修订切换和关系投影，不产生部分写入。

## 读取与界面

- `GET /api/v1/relationship-types` 返回当前关系 Schema。
- `GET /api/v1/entities/{slug}/relationships` 支持 `outgoing`、`incoming`
  或 `both`，并可按 `typeId` 过滤。
- 返回项同时包含关系实例、关系类型、方向和邻接实体；反向遍历使用 `inverseName`。
- 公开条目关系块和 `/relations/{slug}` 浏览器均消费同一接口，不从前端猜测关系文案。

P0 不引入独立图数据库。只有在真实多跳查询、中心性计算或大规模图算法证明 PostgreSQL
投影不足时，才增加可重建的图投影。
