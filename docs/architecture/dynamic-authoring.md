# 动态 Schema 与受治理条目创建

## 目标

百科内核不为动物、植物或电子元件分别编写固定表单。`EntityType`、`AttributeDefinition`
与 `ViewDefinition` 共同定义一种知识对象的字段、校验规则、允许分类与公开页面结构。新增领域
只需注册版本化领域包，不需要修改内核数据模型。

## 运行链路

1. `GET /api/v1/schema-registry` 返回当前实体类型、字段与视图定义。
2. 管理后台 `/entries` 根据注册表生成表单和页面块预览。
3. `POST /api/v1/authoring-drafts` 在当前身份的工作区创建私有草稿；后续
   `PUT /api/v1/authoring-drafts/{id}` 使用 `expectedVersion` 乐观锁更新，避免两个
   编辑会话静默覆盖。刷新或重新登录后可从编辑中草稿列表恢复。
4. `POST /api/v1/entity-drafts/validate` 在服务端校验：
   - slug、必填项、数据类型、基数、枚举和字段约束；
   - 分类节点是否存在、是否属于知识空间、是否被实体类型允许；
   - 新条目是否包含来源证据。
5. `POST /api/v1/authoring-drafts/{id}/submit` 在同一状态机中把 `editing` 草稿
   转为 `submitted`，并创建受治理提案，不直接写入公开库。重复提交同一已提交草稿
   返回已有提案，不重复创建。
6. `GET /api/v1/entities/{id}/authoring-draft` 将当前不可变修订投影回同一个
   `EntityDraft` 合约，并同时返回钉住的基础修订、实体类型、字段和页面视图。
7. 修订草稿提交时对现有条目生成顶层结构差异；实体 ID、类型和稳定 slug 不允许在
   普通内容修订中改变，基础修订必须仍是当前修订。
8. 提案通过策略与人工审核后进入发布批次。
9. 发布生成不可变实体修订，构建完整搜索快照，再切换读取索引。
10. 回滚会恢复既有实体修订，并撤下该发布中新建的实体。

## 扩展约束

- `allowedTaxonomyNodeIds` 是实体类型和分类树之间的明确边界，防止同一知识空间内的跨类别误挂。
- Schema 文档以 `(id, schemaVersion)` 不可变保存；修改定义必须提升版本。
- 表单只是 Schema 的一个消费者，Agent 提取器、批量导入器和第三方客户端必须复用同一校验接口。
- View block 使用内核白名单，领域包只能组合受支持的安全块，不能注入任意前端代码。
- 创建提案中包含完整草稿快照和引用标识；正式发布会重写修订、数据、Schema 与策略版本。
- 修订提案保存每个变化路径的精确 `before` 值。基础修订在草稿生成时已钉住，提交时
  先检查一次；若审核期间当前条目再次改变，发布阶段仍会因 `before` 冲突拒绝陈旧提案。
- 新增来源可以和正文、章节、Claim 在同一个修订提案中提交。发布器先验证候选引用集，
  再验证最终 `KnowledgeEntity`，因此新证据不会被误判为未知引用，也不能绕过实体校验。
- 草稿状态仅允许 `editing → submitted | abandoned`，每次写入版本加一；草稿工作区
  只能由认证 Principal 决定，请求正文不能指定或切换工作区。
- `EntityDraft.relationships` 复用内核关系合约。可用关系类型来自
  `EntityType.allowedRelationshipTypeIds`；服务端同时校验目标实体、源/目标类型、
  双向基数、限定字段 Schema、证据引用和目标引用完整性。
- 条目修订中的关系是源实体出边的完整替换集。持久层在校验新集合时排除即将被替换的
  旧出边，因此关系 ID 或目标变化不会被旧边错误触发基数冲突；发布仍以事务方式同步
  当前关系边投影。

## 管理工作台

Admin `/entries` 是独立于 Schema 设计器的内容生产入口：

- “新建条目”根据当前实体类型动态生成属性、分类和安全页面块；
- “修订现有条目”从当前修订恢复完整草稿并禁用 ID、类型与 slug 变更；
- “保存私有草稿”把当前字段与来源完整保存到工作区；顶部恢复栏可在刷新后继续编辑；
- “Schema 动态关系”根据 Domain Pack 生成关系类型、目标条目、限定字段、引用和
  置信度控件，关系预览与正文预览共用当前草稿；
- 右侧预览只消费白名单 `ViewDefinition` 和当前表单状态，不执行领域代码；
- 校验失败不创建提案；校验成功只进入治理队列，编辑器没有直接发布按钮；
- 浏览器只访问 Admin 同源 BFF，OIDC 令牌和 API 地址不暴露给客户端 JavaScript。

## 当前边界

当前版本实现通用创建、发布和回滚、Schema 影响分析、双人审核门、确定性转换、原子
Schema/实体切换和反向回放。Schema 本身的变更始终作为高风险提案审核。详见
[`schema-migrations.md`](schema-migrations.md)。
